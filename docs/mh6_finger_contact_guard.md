# ESP32 五指接触限力保护（实验分支）

分支 `codex/finger-contact-guard` 从单向分支 `2f969ec` 建立。
只做离线测试和编译；未烧录、未执行电机运动。出厂代码保持 **运动锁定**，不能直接拿来抓取物体。

## 协议核对

本分支以仓库根目录 `MicroServoControlProtocal.pdf` 为依据，其封面为 **V2.0.4**，
明确说明兼容旧版并增加力控等模式。之前“当前必须用 v1.8.3”的判断不成立：
旧代码使用旧指令能运行，并不能证明电缸不支持新协议。

V2.0.4 的相关功能（PDF 印刷页码）：

| 项目 | 定义 |
|---|---|
| 状态查询，8–9 页 | `0x30`；目标/实际位置、电流、力、ADC、温度、故障 |
| 寄存器读/写，9–11 页 | `0x31` / `0x32`，16 位小端寄存器地址和数据 |
| 输出上限，12 页 | `0x21/0x22`，0–1000；这是驱动输出上限，不是恒流控制 |
| 行程上/下限，12 页 | `0x23/0x24` |
| 模式/力/速度/位置，12 页 | `0x25/0x27/0x28/0x29` |
| 力控，21–23 页 | 模式 3：动态调整位置来维持受力；位置寄存器不提供目标位置约束 |
| 速度力控，26–27 页 | 模式 5：向位置目标运动，超过力目标停止；未承诺自动恢复或恒力保持 |
| 故障清除/急停/暂停，11 页 | `0x18/0x19/0x1A` 写 1 |

手册存在排版/文字不一致，不能机械照抄单段示例：

1. 26 页文字把力目标写为 `0x26`，12 页寄存器表及 27 页完整报文都对应 **`0x27`**。
   本分支采用后者；`0x26` 为电压字段，始终写零，不使用电压模式。
2. 状态请求的 8 页通用结构为长度 3、命令 `0x30` 加两字节保留地址；
   12–13 页例子的长度字段写成 1，却仍列出两字节地址。
   本分支采用通用帧结构 `55 AA 03 ID 30 00 00 SUM`，长度/校验按实际字节计算。
3. 状态响应的数据段长度为 `0x0F`，整帧为 **20 字节**：B7–B18 为 12 字节状态，B19 校验。
   电流 B11–12、力 B13–14、ADC B15–16、温度 B17、故障 B18，不能沿用旧版 22 字节的解析。

力单位沿用协议 g（克力标度），不是已标定的指尖接触力。
操作者已确认五根电缸属于 **LASF** 系列；手册印刷 1–2 页明确其具有力传感器。
操作者同时确认抓握时受力反馈为正值，F1–F5 的 `forceSign` 已设为 `+1`。
系列名可以作为选择力控方案的依据，但不能证明安装的电缸固件版本、力传感器有效性、
原生模式及行程限制行为已经完成实测。
不自动修改力零位，也不向执行器 Flash 保存参数。

## 最新目标优先与状态

每指只保存一个最新 `desired`，每份合法新命令立即覆盖它，没有待执行的历史目标队列。
保护内部的已规划目标 `applied` 与真实反馈位置分开；主机发送完成不代表它们相等。

| 状态 | 动作 |
|---|---|
| WAITING | 未收到目标；只查询反馈，不发送运动 |
| FOLLOWING | 闭合采用原生速度力控模式 5，加软件位置斜坡和前向行程包络 |
| HOLDING | 接触力持续超过阈值后采用模式 3，目标为安全抓持力，不发送旧的深闭合目标 |
| OPENING | 新张开目标取消力控保持，用原生速度模式 2 直接追踪新目标；速度受执行器参数限制 |
| STALE | 反馈超时或命令超过时限，发送暂停，不再自主追赶旧目标 |
| FAULT | 过大力、持续过流、过温、驱动故障、位置异常或通信错误：急停并锁存 |

“优先”不表示新闭合指令能绕过力、电流、温度保护；硬故障时新张开指令也不能自动解除急停锁存。
若最新目标虽然比原来小，但仍大于接触位置，只替换期望位置并继续安全抓持；
若目标已小于实际/已规划位置，则立即取消抓持状态并向新位置张开。

接触时锁定力控行程上限为接触位置加 `maximumLeadSteps`，且不超过最新期望位置及机械上限。
不能把上限不断改成“最新反馈位置+余量”，否则物体移走后可能在等待脱离判定期间连续向前爬行。
受力持续低于 `releaseForceG` 后回到速度力控，从当前实际位置追赶 **最新目标**，不会回到旧目标。
原生力控是否严格执行行程限制是实机必须验证的一项，代码不能代替该验证。

停止命令更新默认 500 ms 后暂停，防止断开后移走物体引发自主闭合。
正常抓持不执行急停/张开/故障清除；严重故障无法保证继续抓牢。
清错只接受显式请求，须有新鲜、低负载反馈；成功清错后撤销原目标，等待新命令。

## 参数填写与锁定

唯一的保护参数入口是 `DHandControl/DH6Modbus/FingerGuardConfig.h`，
参数类型及验证规则在 `FingerGuard.h/.cpp`。
默认 `FINGER_GUARD_ARMED=false`，已填写操作者批准的低力试验初值，UART 仍轮询只读状态。
单控、组控、组合控制和原子包都不能绕过未配置锁；`legacy` 遥操作同样检查固件保护能力。

`fingerGuardLimits(id)` 已将 F1–F5 分成五个独立配置块。
位置范围显式填写为 20–1950；计时、速度和前向余量保留原测试初值。
受力符号已经按操作者确认填写 `+1`，不属于剩余待填项；这不自动确认空载基线或力控行为。
F1–F5 均已写入下表试验初值。它们是调试建议，不是厂商额定值，也未通过本手实测。
两项验证标志仍为 `false`，填入数值不会自动解锁运动。

| 字段 | 当前值 | 单位/含义 |
|---|---|---|
| `forceVerified` | false | 确认此指的力反馈有效、空载基线合适后填写 |
| `nativeModesAndLimitsVerified` | false | 确认原生模式、行程限制、退出行为及原有过流设置后填写 |
| `forceSign` | +1 | 操作者确认抓握反馈为正 |
| `minimum/maximum` | 20/1950 | 执行器位置单位，与 `mh6_hardware.json` 一致 |
| `releaseForceG` | 100 g | 低于此值持续 `releaseMs`，视为阻力消失 |
| `contactForceG` | 300 g | 达到此值持续 `contactMs`，进入抓持 |
| `holdForceG` | 400 g | 原生模式 3 的抓持目标 |
| `limitForceG` | 600 g | 模式 5 的接近限力阈值 |
| `dangerForceG` | 1000 g | 力绝对值达到此值，急停锁存 |
| `continuousCurrentMa` | 800 mA | 超过持续 `overCurrentMs` 则故障，须低于最终过流阈值 |
| `tripCurrentMa` | 1200 mA（待核对原值） | 立即故障阈值，并写入原生过流保护寄存器 `0x20` |
| `maximumTemperatureC` | 45 ℃ | 达到即故障 |
| `outputLimit` | 200 | 1–1000 驱动输出量程，不等于电流或力 |
| `speedStepsPerSecond` | 300 步/秒 | 保留原测试参数，不是实机验证值 |
| `maximumLeadSteps` | 10 步 | 接触时前向余量，保留原测试参数 |
| `contactMs/releaseMs/overCurrentMs` | 30/60/100 ms | 接触/释放/持续过流判定时间 |
| `feedbackTimeoutMs/commandTimeoutMs` | 100/500 ms | 反馈及命令超时 |

试验初值的前提是空载受力明显低于 100 g。实际空载基线若不满足，须先核查传感器和机构，
不能把这组值当作已经完成标定。

**1200 mA 尚未核对电缸原有过流阈值，不能因此解锁。**当前代码会直接写入该字段，
尚无自动读回或取小逻辑。启用前先读取每指原生寄存器 `0x20`，将 `tripCurrentMa` 设为
`min(1200 mA, 原有设置)`；若结果小于等于 800 mA，还须降低 `continuousCurrentMa`，
使其严格小于最终的过流阈值。不能通过修改验证标志跳过这项核对。

要求 `0 < release < contact <= hold < limit < danger`，
`0 < continuousCurrent < tripCurrent`，全部启用指的配置通过后才能运动。
上述初值按操作者授权写入，不代表实机安全结论；单元测试仍使用独立的模拟负载。

以下只是当前代码的整数编码/校验范围，**不是 LASF 额定值或实机推荐值**：

| 参数 | 代码允许的范围 |
|---|---|
| 五个力阈值 | 正整数，均不超过 30000 g，同时满足上述顺序关系，不能各自独立随意选取 |
| `continuousCurrentMa` | 1–65534 mA，且小于 `tripCurrentMa` |
| `tripCurrentMa` | 2–65535 mA，且大于 `continuousCurrentMa`；会写入电缸原生过流寄存器 |
| `maximumTemperatureC` | 1–80 ℃ |
| `outputLimit` | 1–1000，驱动输出量程，不是电流值或力值 |
| `contactMs/releaseMs/overCurrentMs` | 1–65535 ms，当前初值 30/60/100 ms |
| `feedbackTimeoutMs` | 20–500 ms，当前初值 100 ms |
| `commandTimeoutMs` | 100–2000 ms，当前初值 500 ms |

实际可用范围还必须受具体电缸规格、手指机构和抓持负载约束；不能把编码上限作为试验上限。

`FINGER_GUARD_MASK` 默认 `0x1F`，每位对应 F1–F5。
单指台架验证可只启用一位，其他手指只读不发运动，手掌禁止运动；
遥操作入口则强制要求五指全部启用，防止把单指配置误用于整手抓取。

### LASF 手册能提供和不能提供的参数

- 印刷 12 页给出单位、寄存器和数值编码范围，不是各具体电缸的额定负载表。
- 印刷 22–23、27 页的 1000 g 属于指令示例，不是本手五指的推荐抓持力。
- 电缸当前的过温 `0x1E`、过流 `0x20` 和正/反向输出上限 `0x21/0x22` 可通过
  原生读寄存器命令获得；当前缓存反馈工具只读状态，**尚不读取这些配置寄存器**。
  读回的值也不等于已经验证了装配后手指的安全抓持范围。
- 释放/接触/抓持/限力/危险力阈值仍须按实际机构与负载确认。
  抓握受力为正由操作者确认，不是根据位置增加自行推断。

因此本次 LASF 配置整理仍保持 `FINGER_GUARD_ARMED=false`，不会把“系列支持力控”
自动转成“已通过原生模式及力传感器验证”。

## 调度和手掌联锁

五指共享串口只有一个读写所有者，一次只挂起一个事务。
每 4 ms 安排一个轮询槽，正常情况下每指约 50 Hz；原生写命令自身返回的状态同时更新反馈。
收包分片、ID/命令/寄存器/长度/校验不匹配均不能更新有效反馈。
超时后隔离晚到数据，再轮询；错误锁存后不会因收到新闭合目标而自动恢复。
开手请求可优先占下一空闲槽，但会照顾已超期的其他手指，避免饥饿。
该频率是调度目标，未在实机证明最坏响应时间。

手掌没有等价力/电流反馈，第一版不实现手掌力控。
任一手指故障、反馈缺失/过期或只有部分手指启用时，阻止四路手掌继续接收新运动目标；
M1–M3 整组冻结，不拼接单路闭环解。正常接触抓持时手掌仍采用原控制逻辑，
故初期台架测试应固定手掌，不能声称该保护覆盖整只机械手的全部风险。

上位机 `--no-feedback` 仅关闭主机的逐帧反馈读取，不关闭 ESP32 本地保护反馈。
手掌反馈的原阻塞查询仍保留；高频遥操作先保持 `--no-feedback`，避免增加 MCU 调度负担。
本分支不允许旧电缸 ID 读改接口抢占保护串口；ID 配置使用原分支/独立调试固件。

## 能力检查、确认和诊断

保护固件能力寄存器 50–52 为 `[0x4D36,1,7]`。
主机额外检查 80–83 为 `[0x4647,1,0x1F03,0x0204]`，确认五指配置已启用。
这只验证代码配置，不证明实机传感器正确或电缸模式已实测。
旧 ACK/单向固件能力为 3，不能在本分支冒充已有保护。

ACK 成功码改为 `0x95`：`GUARDED_TARGET_ACCEPTED`，表示最新目标被保护层接收，
不是所有电机已收到目标，更不是到位。单向仍不逐帧产生响应。
80–165 是只读缓存诊断区，不能通过 Modbus 写入来伪造已启用状态。

停止其他占串口程序后，由操作者执行只读检查（代理没有执行）：

```bash
python DHandControl/scripts/mh6_finger_guard_status.py --port /dev/ttyUSB0 --watch \
  --output results/finger_guard/feedback_01.jsonl
```

该工具不清错、不校零、不写参数、不发位置。可以在未启用运动时采集五指力/电流/温度基线。
它与单向发送不能同时通过两个进程抢占同一串口。
字段区分最新期望位置、已规划位置、真实反馈位置，并报告有效反馈年龄、状态和故障原因。

需要自动结束并保存统计时，由操作者执行以下 10 秒只读采集：

```bash
python DHandControl/scripts/mh6_finger_guard_status.py --port /dev/ttyUSB0 \
  --duration 10 --output results/finger_guard/lasf_baseline_01.jsonl \
  --summary-output results/finger_guard/lasf_baseline_01.summary.json
```

此命令需要先烧录本分支保护固件，运动开关可以保持关闭。采集时保持无物体接触、无外部加载，
停止其他占用串口的程序。再次采集时换文件名；已有文件不会覆盖。
汇总统计仅采用新鲜、无故障且应答计数变化的样本，重复缓存、无应答和过期值不充当有效测量；
记录力的最小/最大/均值、电流/温度/位置范围及无效次数。主机采样约 5 Hz，不能据此推断
电缸反馈峰值或 MCU 最坏保护响应时间。
空载汇总不自动推定安全负载、闭合受力方向，也不修改或解锁固件。

每指 16 字寄存器，从 `86+16*(id-1)` 开始：状态、原因、desired、applied、实际位置、
力、电流、温度、反馈年龄、故障位、有效应答计数高/低字、原生模式、行程上限、命令年龄、反馈新鲜标志。
全局 80–85 为标识、格式版本、启用位/配置标志、协议版本、抓持数量、异常位图。

## 验证边界

测试在内存 UART 与主机 C++ 编译器上执行实际状态机、调度器和完整 `.ino`：
目标替换、接触保持、负载移除、张开覆盖、固定力控包络、方向符号、时间戳回绕、
电流/力故障、反馈/命令超时、分片/坏校验/错 ID/错命令/错地址、单向无应答、默认锁定及缓存只读。
Arduino 编译使用通用 `esp32:esp32:esp32`，只证明可编译，不表示替用户选好了真实开发板。

仍需操作者完成：具体规格确认、原生模式及限位验证、力传感器空载基线检查、
每指安全连续电流和温度确认、单指低负载测试、夹持保持/移走/主动张开测试、
测量最坏反馈周期和保护响应时间。未完成前不应解锁整手遥操作。
